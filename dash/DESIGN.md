# Usage dashboard design

Local Bun app in the kit folder at `dash/`. `bun run dash` incrementally parses new transcript bytes into `~/.agent-handoffs/usage.db` (override with `DASH_DB`) (bun:sqlite, kept forever, outside the repo) and serves `localhost:4319`. Nothing leaves the laptop; the header says so. Dark, dense UI (Linear/Vercel analytics feel); charts follow the dataviz skill. Store numbers, tool names, file paths, MCP server names, AI titles only. Never prompt or tool-result text.

## Views
1. Overview (week; day/month toggle): API-equivalent $ this week vs last, value as a multiple of a monthly plan price (`proMonthlyUsd` in `config.json`, prorated), tokens by input / cache write / cache read, cache hit rate, avoidable $ (flags); daily $ stacked by model; opening context trend; worst 5 sessions by avoidable $ with flag chips; handoff count.
2. Sessions table: sort/filter by project, model, kind (main / subagent / worker-probe), $, peak context, turns, duration, flags; label = `ai-title`; badge "continued from" for handoff sessions.
3. Session detail: context growth, one point per deduped API request, cache read/write bands, idle gaps, flag markers with $; opening breakdown bar; top 10 tool results; full tool-call table on click.
4. Opening context: per session split into system prompt, built-in tools, each MCP server, skills listing, CLAUDE.md+memory (`instructions` attachment), deferred tools, agent list, MCP instructions. Also context at end of the first prompt (before the 2nd human message). Trend line.
5. agent-kit: before vs since agent-kit, in plain language with no run IDs. The boundary is `agentKitStart` in `config.json`: set it to the first full local day after you installed the kit. Using the exact install time would add a partial active day and understate spend per day. Baseline select: all before, or the last 14 days before. An early-data warning shows while the after period has under 14 days used. Six answer cards (each dollar buying more, spending less, lighter start, staying small, cheaper models, warm cache) with Better / Worse / About the same at +-5%; charts for opening by day with a start marker, opening parts, cost per request in 7-day periods counted back from the start, model share of spend; a full comparison table; "What agent-kit changed" from `agentKitChanges` in `config.json`, with its result metrics; worker jobs from `~/.agent-handoffs/ledger.jsonl`, named from the brief file, probes left out, with Kept it / Had to redo buttons that call `bin/verdict.ps1` (the app's only write).
   - Spend and session counts per day use days with at least one request, by local date. Session cost is shown but not scored: handoffs split sessions, so it falls without saving anything.
   - Opening parts compare only from `openingPartsComparableFrom`, the date from which transcripts separate MCP from built-in tools. Built-in tools and system prompt belong to Claude Code, so they get no verdict.
   - Flag dollar amounts are estimates. The changes table lists what moved next to each change; the changes were close together, so it does not claim cause.

## Data facts (verified)
- `~/.claude/projects/*/*.jsonl` and `*/<session>/subagents/*.jsonl`. Subagent lines carry the parent's `sessionId` plus `agentId`; they are indexed as session `<sessionId>/<agentId>` with `parent_id`. Assistant lines: `requestId`, `message.model` (skip `<synthetic>`), `message.usage.{input_tokens, cache_creation_input_tokens, cache_creation.ephemeral_1h_input_tokens/ephemeral_5m_input_tokens, cache_read_input_tokens, output_tokens, output_tokens_details.thinking_tokens, server_tool_use.web_search_requests}`, `timestamp`, `cwd`, `gitBranch`, `isSidechain`, `effort`, `sessionId`.
- DEDUPE by session/agent identity plus `message.id`, falling back to legacy `requestId` or record UUID when necessary. Streamed cumulative usage fields merge by maximum, not by first snapshot or sum. Resumed copies of the same session count once; main/subagent message identities stay separate, including legacy agent filenames. Missing base usage, invalid values, unknown model prices and unspecified cache-write TTL remain explicitly incomplete.
- Tool results: user lines with `toolUseResult`, `sourceToolAssistantUUID`, `attributionMcpServer`, `attributionMcpTool`.
- `api-request-shape` line: `shape.system[]`, `shape.tools[]` (name `mcp__<server>__<tool>`, `defer_loading`). Only in CC >= ~2.1.300. First `api-request` (`querySource: repl_main_thread`) has `tail[]` hashes into `api-request-blob` messages.
- Attachment lines: `attachment.type` in skill_listing, instructions, deferred_tools_delta, agent_listing_delta, mcp_instructions_delta, environment, session_context, nested_memory; size = sum of `rendered[].content` lengths. Opening uses the first request shape and distinct rendered attachment deltas before the second real human message. Hashes deduplicate exact replay across chunks/resumes without retaining rendered text; tool-result messages are not human boundaries.
- Opening tokens per component = char share x real first-request total (input+cache write+cache read), about +-15%. No count_tokens API (would send private text).
- `ai-title` line: `aiTitle`. `cost-state` line: `totalCostUSD`, `modelUsage[model].costUSD` (cumulative; take max per session).
- Worker/probe sessions: cwd under the OS temp folder, or session_id in ledger.
- Handoff sessions: first human prompt matches `Read <path>/.agent-handoffs/...md and continue from "Next step".` (the kit's `continue.ps1`). Writer = session with a Write tool call to that path.
- Status line appends `~/.agent-handoffs/.state/statusline.jsonl` on change. The worker stores whitelisted timestamps, session/model identifiers, numeric cost/context and `rate_limits.five_hour` / `seven_day` observations (`used_percentage`, `resets_at`), never arbitrary JSON or prompt content. A source may be absent on Windows; that is unavailable, not zero.

## Pricing ($/MTok: input, output, 5m write, 1h write, read)
- claude-opus-5-5: 4, 20, 5, 8, 0.20 (verified from claude-api skill)
- claude-sonnet-5-5: 2, 10, 2.5, 4, 0.10. The claude-api skill lists reads at 0.20, but Claude Code's `cost-state` prices them at 0.10 (matches to the cent on main-thread sessions); we follow `cost-state`.
- claude-sonnet-5: 2, 10, 2.5, 4, 0.20 (verified)
- claude-haiku-5-5: 0.10, 0.50, 0.125, 0.20, 0.01 (in/out from skill, prompts <=100K; >100K is 0.50/2.50; writes and read assumed)
- claude-haiku-4-5: 1, 5, 1.25, 2, 0.10; claude-opus-4-8: 5, 25, 6.25, 10, 0.50 (assumed multipliers)
- web search: unknown, assume $0.01/request. Rates live in `dash/prices.json`. Dated ids (`-YYYYMMDD`) use the base id's rates.
- `bun run check-prices` prices each session's `cost-state` token counts with `prices.json` and compares with its `costUSD`: median 0.00% for Opus 5.5, Sonnet 5 and 5.5, and Haiku 5.5. Outliers are sessions with subagent 5m writes, because `cost-state` does not split 5m from 1h. Indexed request cost differs from `cost-state` per session (Opus +12%, Sonnet 5.5 -14%) because `cost-state` covers only part of resumed sessions; the dashboard uses indexed requests.
- Plan price and cache TTL are per-user settings, not universal. The parser never infers a TTL for an unspecified write.

## Waste flags (thresholds in dash/config.json)
- Ran past handoff: context > 200k for >= 5 turns; $ = read cost above 150k on those turns.
- Cold rebuild: cache write > 20k after gap > TTL (60 min for 1h, 5 min for 5m); $ = write cost minus read cost.
- Oversized tool result: one result > 10k tokens (chars x ~0.3); $ = its tokens x later turns x read rate.
- Loaded, never used: MCP server / skill in the opening context with zero calls; $ = tokens x turns x read rate.

## Copilot accounting and comparison contract

The additive **All harnesses** view supports Copilot, Claude and combined selections. Its environment/harness/model filters, local From/Through dates, Agent-kit boundary and baseline control `/api/usage`; `/api/usage/sessions/:id` provides measured per-call details. Claude's existing landing view, configuration, APIs and pricing remain unchanged by default. An instance can explicitly set `DASH_DEFAULT_HARNESS=copilot`. Mixed USD combines different billing bases: Copilot reported usage amounts and Claude API-equivalent estimates, not two invoices.

- Discover `COPILOT_HOME` plus every folder in `sources.copilotHomes` of `config.json` (default `~/.copilot`; `~` expands to the home directory). To add another Copilot home, append its path to that list. `DASH_COPILOT_ROOTS` overrides discovery with semicolon-separated roots; an empty value disables Copilot. Canonical filesystem paths prevent aliases from indexing the same root twice. `DASH_DB` selects a private development index without touching an existing production index.
- Index complete appended JSONL lines in bounded chunks. Persist byte cursors, file identity, mtime and boundary fingerprints. Retain an unfinished final line, reset on truncation/replacement/same-size rewrite, and validate the old prefix/end before reading an append. A rewrite confined to the middle of an old prefix while also appending cannot be detected by boundary fingerprints: set `DASH_COPILOT_RESCAN=1` for an explicit full reparse after external history edits. Normal producer logs are append-only. Removed/configured-out sources are removed from the derived index. Skipped malformed/oversized lines remain visible in coverage.
- `session.usage_record.data.usage.accounting.usageId` is the durable per-call identity. Prefer the original `sourceSessionId` when it identifies a known logical session, otherwise retain the containing session. Fork/export copies and resumes do not add another bill. Harness-prefixed IDs keep Claude and Copilot identities separate. Only whitelisted numeric usage, model/tool names, identifiers and timestamps are stored; message content, tool arguments/results and source prompts are not persisted.
- Conflicting numeric observations for the same durable identity are counted once but left unpriced, with a coverage count and per-call conflict status. Do not silently choose a larger, smaller or later bill. Model groups use the response model; they are not an allocation of mixed-model token billing details.
- `copilotUsage.totalNanoAiu / 1e11` is recorded USD. One AI credit is $0.01. `usage.cost` and SQLite `request_multiplier` are reported premium-request multiplier units, not dollars or AI credits, and are not inferred to be an invoice charge. Null measurements stay unknown; `aiCreditsStatus: partial` remains labelled partial. No network pricing/model/token-count calls are made.
- Read `session-store.db` with SQLite's read-only connection and a consistent read transaction, including live WAL data. Import only whitelisted `assistant_usage_events` columns. Deduplicate identical full measurement tuples, including session, turn, agent, parent-tool identity, model, token counts, nano-AIU, multiplier, duration, reasoning and persistence time. SQLite has no durable usage ID: **exclude SQLite rows for any session with durable records**, rather than attempt timestamp-nearness matching. The same observed call can have event and SQLite timestamps one millisecond apart. This conservative policy deliberately withholds some older resumed-session history; the excluded count/amount and sessions lacking calls are prominent, not silently counted as zero.
- Old shutdown `totalNanoAiu` and new `accountingSnapshot.totalNanoAiu` are aggregate observations, not additional usage. The new schema also records replay watermarks. Repeated snapshots include prior calls, while old history can contain reset/partial summaries. Neither a sum nor a per-session maximum is a defensible universal bill. Show snapshot sum/latest-per-session only as all-history diagnostics, never as spend, per-request cost, or a gap-filling estimate.
- Copilot `inputTokens` is the full measured prompt, including cache read/write tokens. Do not add them again. Cache reuse is cache-read tokens divided by measured prompt tokens. Request count is not human-turn count; summed API duration is not elapsed task time. System/tool token observations from shutdowns are labelled with their observation time, **not opening components**. The first observed request can be mid-session or after missing history.
- Copilot has no inferred rollout date. The user must choose a boundary; Claude alone may use its configured `agentKitStart`. Dates resolve to local midnight, Through includes the whole selected local day, and interval upper bounds are exclusive. The 14-day baseline uses local calendar days. Compare absolute amounts alongside USD/priced-request and active-local-day rates, sessions, measured context/cache and model/harness mixture. Warn on small samples and missing coverage; do not infer accepted/completed work or causal savings.

The server builds its complete local production assets before binding `127.0.0.1:4319` (`DASH_PORT` may choose another loopback port for isolated development): the first root request never triggers a lazy HTML bundle. Initial indexing and minute-by-minute refreshes run on a worker thread with their own SQLite connection, not on the HTTP event loop. The serving connection is read-only; derived rebuilds publish atomically and GET queries use consistent read transactions. Date/session restrictions are applied in SQLite before materializing drilldown data. A listening log is emitted only after the bundle and initial index are ready. No usage data, fonts, analytics or pricing requests leave the machine.

Run `bun test` for deterministic Copilot/Claude and server-readiness regression fixtures. `test/parity.test.ts` runs the real independent `bin/analyze-transcripts.mjs` CLI and the dashboard index/query path on the same corpus with explicitly sourced equivalent pricing and unspecified TTL left unpriced. It compares all token components and known USD to 12 decimal places, including streamed cumulative chunks, replays/resumes, main/subagent identity, unknown models and incomplete usage. Claude's legacy overview, session ranking and combined usage views share those known-cost amounts; incomplete components are labelled, not represented as a complete invoice. Acceptance is ranking and bounded script parity. The test is skipped when `bin/analyze-transcripts.mjs` is not present in the kit.

### Independent environments

`DASH_ENVIRONMENT` (default `local`) and `DASH_ENVIRONMENT_LABEL` label this instance's data. Use a distinct `DASH_DB` for each extra instance; do not point development at another deployment's active index. Existing installations require no new configuration and retain the Claude overview as their landing page.

Optionally set `DASH_ENVIRONMENTS_FILE` to a **local**, user-owned JSON array, outside the repository. Each entry has `id`, `label`, and optionally `index` (a local dashboard SQLite index), `statusline` (a local read-only JSONL observation source), `claudeBoundary`, and `copilotBoundary`. Relative paths resolve beside that JSON file. An entry without an index is explicitly unavailable for transcript usage, not zero usage; its explicitly supplied statusline can independently provide limits. Additional indexes are opened with SQLite `readonly: true` and a read transaction; they are never migrated, indexed, refreshed, copied or written by this instance. This permits an explicitly supplied local index to appear alongside the current instance without changing its configuration or rollout date. It does not retrieve another laptop's data.

The environment selector offers each configured environment and all local indexes together. Individual selections keep their own boundaries and source coverage. An explicit combined comparison has no automatic cutoff. Request identities are deduplicated across selected indexes, preferring current-instance provenance for identical copies; conflicting costs are left unknown and counted. Harness/environment labels remain on model groups, sessions and drilldowns. The coverage table reports each source separately. Dates chosen in the UI are independent for each environment/harness selection and do not write to either source's config.

### Subscription limits

The legacy Claude overview and the environment/harness usage view show `/api/limits`. The worker refreshes local sources; HTTP requests never scan source logs. Missing samples, malformed records, exact replays, same-time conflicts, resets, decreases and expired intervals are visible. Burn is the sum of nonnegative percentage-point deltas between adjacent valid observations sharing the same window reset, divided by their measured hours for a rate. Missing-window observations interrupt coverage. A single measured zero is 0% used but has **unavailable burn**, not measured zero burn. Long sparse intervals only describe endpoint change; they do not establish continuous coverage or recover unobserved reset consumption.

Limits remain per environment and per 5-hour/7-day window, never summed across environments or substituted for Copilot credits. Model filters do not attribute an account-wide quota to a response model. From/Through filters bound both endpoints; the UI labels sampled timestamps, cumulative session cost and context separately. No USD-per-percentage conversion, projection or quota size is inferred from historical rough ratios. Existing config files and deployments are never rewritten to enable the view.

## Configuration

Defaults in `config.json` are generic. `sources.claudeHome` (default `~/.claude`) holds `projects/` transcripts; `sources.copilotHomes` lists Copilot homes (default `["~/.copilot"]`). Codex (`~/.codex`) is not indexed yet; see Open work. Paths are built from the home directory with `path.join`, so they work on Windows, macOS and Linux. `DASH_PROJECTS_DIR`, `DASH_HANDOFFS_DIR`, `DASH_DB`, `DASH_COPILOT_ROOTS`, `DASH_ENVIRONMENT`, `DASH_ENVIRONMENTS_FILE` and `DASH_PORT` override them per run. `agentKitChanges` starts empty: add `{ "date", "change", "metrics" }` entries to list what you changed and which metrics to show beside it.
